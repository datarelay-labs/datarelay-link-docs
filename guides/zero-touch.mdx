# Zero-Touch Enrollment

On the DRLink Server:

```text
set enrollment zero-touch
```

DataRelay Link generates an installation command for the intended host.

## Security limits

```text
maximum per issuance request     10
maximum active unused tickets   10
default TTL                     1 hour
maximum TTL                     24 hours
use count                       1
```

Each enrollment credential is unique. Keep raw enrollment credentials confidential. Persistent Server state stores a verifier and lifecycle metadata.

A successful enrollment atomically consumes the ticket. Reusing a consumed ticket is denied.

## Important boundary

Zero-Touch enrolls the Agent. It does not create OS users, change SSH configuration, modify cloud firewalls, or automatically create policy Rules.

## Command fields (next product candidate design)

The customer receives a command with only these fields. Public and private HTTPS use the same form; DNS is optional. Only the Server authority and filename vary.

| Item | Linux/macOS | Windows (administrator PowerShell) |
|---|---|---|
| Downloader | `curl` | `curl.exe` |
| Options | `-kfsS` | `-kfsS` |
| Protocol | `https://` | `https://` |
| Server authority | FQDN or IP, configured port if required | Same |
| Bootstrap filename | `/` + six-character filename | Same |
| Execution | `\|sudo bash` | `iex(...\|Out-String)` |

```bash
curl -kfsS https://remote.xdr.ooo/A3xK9m|sudo bash
```

```powershell
iex(curl.exe -kfsS https://remote.xdr.ooo/A3xK9m|Out-String)
```

These are design examples for the next product candidate, not issued or currently executable enrollment commands. Bootstrap handles all additional files, configuration, verification and recovery. Retry the same command without duplicate enrollment. The filename is not an enrollment credential. The initial `-k` download does not authenticate the Server; downstream connections, separate enrollment authorization and actual OS qualification must be verified before product release. SSH username may be blank.

## Automatic setup and additional services

Services selected through Zero-Touch **SSH only**, **RDP only** or **Choose Remote Services** automatically receive the required Service Object, Remote Service and public endpoint reservation during enrollment. Do not create the same service manually again. Inspect actual names with `show remote-services` on the Agent.

**A blank username in SSH only affects connection hints; it is not management-only enrollment.** To enroll without publishing services, run `set enrollment bulk`, choose count **1** and leave the SSH username blank. Choose Remote Services requires at least one service. OS accounts, sshd/RDP, external firewalls and Access Policy rules remain separate.

Only when adding a new destination/port to an existing Agent, inspect/prepare the Server Object definitions and use `set remote-service <NAME>` on the owning Agent.
