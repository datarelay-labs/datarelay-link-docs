# Quick Start

<Warning>
  These instructions describe the **v2.4.0 development target**. Before a stable v2.4.0 release exists, use an exact immutable SHA or an explicitly qualified candidate artifact supplied for testing.
</Warning>

## 1. Verify the Server

```bash
sudo drlink
```

Then run:

```text
show version
show status
system diagnostics
```

The role must be **DRLink Server**.

## 2. Ensure the Service Object exists

For SSH:

```text
set service-object ssh type tcp port 22
```

## 3. Issue a Zero-Touch enrollment

On the Server:

```text
set enrollment zero-touch
```

Run the generated one-time installation command on the target host.

## 4. Verify the Agent Host

On the newly enrolled host:

```bash
sudo drlink
```

Then:

```text
show status
show agent
```

The role must be **Agent Host**.

## 5. Create the Remote Service on the Agent Host

```text
set remote-service ssh-access destination this-host service ssh enabled
show remote-service ssh-access
```

The endpoint is allocated and managed by DataRelay Link. Temporary Server or target failure can leave a valid Remote Service in DEGRADED state.

## 6. Optional: restrict Remote Access

With no policy configured, effective access is ALLOW.

On the Server:

```text
set network-object office-admin type ip value 203.0.113.10
set remote-access office-ssh mode whitelist source office-admin destination <managed-host> service ssh enabled
test remote-access source office-admin destination <managed-host> service ssh
```

## 7. Connect

Use the endpoint shown by the Agent:

```bash
ssh -p <public-port> <username>@<public-hostname>
```

DataRelay Link does not create OS users or configure sshd; the target account/service must already exist.
