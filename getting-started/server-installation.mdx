# Server Installation

<Note>
  The latest published stable release is **v2.3.0**. This site documents the current **v2.4.0 development target**. Use an immutable release tag for stable deployment or an exact qualified SHA/artifact for v2.4 testing.
</Note>

## Server role

The Server is Linux-based and owns enrollment, Managed Host inventory, Objects/Groups, Access Policies, AI Identity, audit, backup/restore, and Server ConfigurationBundle.

For v2.4 candidate testing, use the exact source/artifact identity provided by the qualification process rather than mutable main/latest.

## Verify after installation

```bash
sudo drlink
```

Then:

```text
show version
show status
system diagnostics
```

Confirm the role is **DRLink Server** and that product version, release channel, exact Source HEAD, and Relay Engine version are truthful.

## Public identity

The installer may use a public IP or configured public domain as the product-facing identity. The selected identity must be used consistently by generated enrollment/Zero-Touch links and other user-facing URLs.

Friendly Remote Service aliases and bootstrap hostnames are separate concerns and must not silently change management identity.

## External boundary

DataRelay Link does not silently configure cloud security groups, external NAT/DNAT, customer DNS records, OS users, SSH configuration, or application TLS certificates.
