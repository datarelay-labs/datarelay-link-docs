# 원하는 활용 사례를 선택하세요

이 문서는 기능 소개가 아니라 **따라 하기 매뉴얼**입니다. 각 시나리오에는 네트워크 구성, 준비 사항, **서버와 Agent별 입력 명령어**, 실제 통신 확인, 차단 테스트, 장애 복구가 포함됩니다.

<Warning>
  다음 명령어는 **v2.4.0 개발 대상 CLI** 기준입니다. 현재 GitHub의 공개 안정 릴리스는 **v2.3.0**이므로, v2.3.0 설치에 v2.4 명령이 그대로 동작한다고 가정하지 마세요. 반드시 **sudo drlink system version**으로 실제 버전·채널·Source HEAD를 확인하고, 검증된 불변 SHA/후보 아티팩트로 작업하세요.
</Warning>

*그림 2. Agent Host의 실제 menu 화면: Remote Services는 1번, ConfigurationBundle은 3번을 선택합니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


1. [서버 설치](/ko/getting-started/server-installation), [배포 모드](/ko/deployment/modes), [방화벽/NAT](/ko/deployment/firewall-nat)을 먼저 완료하세요. Remote Access와 AI Access에는 적절히 등록된 Agent가 필요하지만, HTTP(S) Internet Access의 보호 대상 호스트는 **Agent 없이 표준 프록시 설정만** 사용할 수 있습니다.
2. **DRLink Server의 일반 셸**에서 현재 상태를 확인합니다.

~~~bash
sudo drlink system version
sudo drlink show status
sudo drlink system diagnostics
~~~

3. **Server REPL**은 서버에서 **sudo drlink** 실행 후 나오는 **drlink>** 프롬프트입니다. **Agent REPL**은 해당 Agent Host에서 여는 프롬프트입니다. **보호 호스트/외부 PC** 명령은 해당 시스템의 일반 셸에서 실행합니다. 서로 다른 호스트의 명령을 섞지 마세요.
4. 샘플 IP, DNS, 사용자명, 호스트 이름, 예약 포트는 **반드시 본인 환경의 값으로 바꾸세요**. 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24는 인터넷 라우팅용이 아닌 문서 예제 주소입니다.
5. **정책 테스트의 ALLOW는 실제 접속 성공이 아닙니다.** 반드시 실제 SSH/웹/Git/APT/AI 호출과 DENY 로그를 확인합니다. 단순 시간 초과는 정책 DENY를 입증하지 않습니다.
6. 운영 정책 변경 전에는 기존 허용 범위, 백업 및 서비스 중단 가능성을 검토하세요. DRLink는 외부 방화벽·DNS·SSH 사용자·애플리케이션 TLS 인증서를 자동 변경하지 않습니다.

CLI 동작이 예제와 다르면 **help commands**, **system diagnostics**, [CLI 참조](/ko/drlink/cli-reference), [문제 해결](/ko/operations/troubleshooting)을 확인하고 임의의 구버전 명령어를 사용하지 마세요.
