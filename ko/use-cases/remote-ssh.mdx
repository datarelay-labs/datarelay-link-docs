# NAT 뒤 내부 Linux 서버에 원격 SSH 접속하기

**완성 결과:** VPN으로 내부 네트워크 전체를 연결하지 않고, 외부 엔지니어가 DRLink Server의 지정된 포트를 통해 내부 Linux 호스트의 SSH에 접속합니다.

**구성 예:** 외부 PC → 공인 DRLink Server → Agent의 아웃바운드 터널 → 내부 10.10.20.15:22.

## 준비

- [서버 설치](/ko/getting-started/server-installation) 완료, v2.4 검증 아티팩트와 외부 방화벽 경로 확보
- 내부 호스트에서 DRLink Server로 아웃바운드 통신 가능
- 내부 호스트에 **이미 동작하는 sshd와 SSH 사용자 계정/키** 존재. DRLink는 계정이나 sshd를 생성하지 않습니다.
- 원격 접속을 외부에 공개하기 전에 필요하면 [접근 허용 IP 제한](/ko/use-cases/office-allowlist)을 먼저 설정하세요. **Remote Access의 초기 No Policy 상태는 ALLOW**입니다.

## 1단계 — 서버 상태 확인

![실제 Data Relay Link CLI 캡처 — 실제 제품 버전 조회: development 채널, Source HEAD 및 DRLink Server 역할을 확인합니다.](/images/cli-captures/server-version.png)

*그림 1. 실제 제품 버전 조회: development 채널, Source HEAD 및 DRLink Server 역할을 확인합니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


**DRLink Server 셸:**

~~~bash
sudo drlink system version
sudo drlink show status
sudo drlink system diagnostics
~~~

**확인:** Role이 **DRLink Server**이고 설치 채널/버전/Source HEAD가 의도한 v2.4 후보인지 검증합니다.

## 2단계 — SSH Service Object 생성

![실제 Data Relay Link CLI 캡처 — Server에서 2번 Create Service Object를 선택하여 프로토콜과 목적지 포트를 정의합니다.](/images/cli-captures/server-service-object-menu.png)

*그림 2. Server에서 2번 Create Service Object를 선택하여 프로토콜과 목적지 포트를 정의합니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


서버에서 **sudo drlink**를 열고 **Server REPL**에서 실행합니다.

~~~text
set service-object ssh type tcp port 22
show service-object ssh
~~~

**확인:** Service Object의 타입 **TCP**, 대상 포트 **22**. 같은 이름이 이미 있으면 덮어쓰기 전에 정의를 확인하세요.

## 3단계 — Zero-Touch 등록 발급

**Server REPL:**

~~~text
set enrollment zero-touch
show enrollments
~~~

화면에 출력된 **실제 일회용 설치 명령어 전체**를 복사하여 내부 Linux 호스트의 관리자 터미널에서 실행합니다. 예시 URL을 임의로 만들지 마세요. 등록 URL/티켓은 비밀 인증정보이므로 공개 문서·이슈·로그에 복사하면 안 됩니다.

## 4단계 — Agent 확인과 Remote Service 생성

![실제 Data Relay Link CLI 캡처 — 실제 Agent Host 상태: Agent 역할, Healthy 런타임 및 Server Connected를 확인합니다.](/images/cli-captures/agent-status.png)

*그림 3. 실제 Agent Host 상태: Agent 역할, Healthy 런타임 및 Server Connected를 확인합니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


![실제 Data Relay Link CLI 캡처 — 소유 Agent Host에서 2번 Create Remote Service를 선택합니다. Server에서 원격 서비스를 직접 생성하는 메뉴가 아닙니다.](/images/cli-captures/agent-create-service-menu.png)

*그림 4. 소유 Agent Host에서 2번 Create Remote Service를 선택합니다. Server에서 원격 서비스를 직접 생성하는 메뉴가 아닙니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


**내부 Agent Host 셸:**

~~~bash
sudo drlink show status
sudo drlink show agent
sudo drlink system diagnostics
~~~

**확인:** Role **Agent Host**, 정상 등록 및 제어 채널 연결.

이제 내부 호스트에서 **sudo drlink**를 열어 **Agent REPL**에서:

~~~text
set remote-service support-ssh destination this-host service ssh enabled
show remote-service support-ssh
show remote-services
~~~

**확인:** DRLink Server에서 할당한 공인 포트/주소가 보이고 대상 및 런타임이 검증되면 **HEALTHY**입니다. **DEGRADED/Pending allocation**은 성공 판정이 아닙니다.

## 5단계 — 외부 PC에서 실제 SSH 접속

![실제 Data Relay Link CLI 캡처 — 실제 SSH Remote Service 검증 결과: HEALTHY 상태와 예약 엔드포인트를 확인합니다. 실제 공인 주소는 가렸습니다.](/images/cli-captures/ssh-service-healthy.png)

*그림 5. 실제 SSH Remote Service 검증 결과: HEALTHY 상태와 예약 엔드포인트를 확인합니다. 실제 공인 주소는 가렸습니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


**외부 PC 셸:** 위에서 조회한 예약 포트·공인 주소·실제 SSH 계정을 사용합니다.

~~~bash
ssh -p <할당된-공인-포트> <실제-OS-계정>@<DRLink-공인-호스트>
~~~

**성공 기준:** 대상 SSH 서버의 호스트 키를 별도로 확인하고 인증을 통과하여 내부 호스트에서 명령을 실행할 수 있어야 합니다. SSH 계정/키 오류는 DRLink 등록 오류와 다릅니다.

## 6단계 — 서버 목록·정책 확인

![실제 Data Relay Link CLI 캡처 — 실제 Remote Access 정책 테스트: No Policy 상태의 ALLOW 결과입니다. WHITELIST 적용 성공 결과는 아닙니다.](/images/cli-captures/remote-test-allow.png)

*그림 6. 실제 Remote Access 정책 테스트: No Policy 상태의 ALLOW 결과입니다. WHITELIST 적용 성공 결과는 아닙니다. 실제 v2.4 개발 후보 CLI E2E/PTTY 기록 발췌; 일부 주소·호스트 가림.*


**Server REPL:**

~~~text
show managed-hosts
show managed-host <실제-Managed-Host-이름> remote-services
show remote-access
system audit
~~~

필요한 SSH 서비스 하나만 노출되었는지, 실제 외부 접속과 감사 기록이 대응하는지 확인합니다. 접속 허용을 제한하려면 [사무실 IP 허용 시나리오](/ko/use-cases/office-allowlist)를 완료하세요.

## 실패 시/철회

- **DEGRADED:** Agent에서 **system diagnostics → system synchronize → show remote-service support-ssh** 순서로 확인
- **시간 초과:** 공인 포트 방화벽/NAT, Agent 터널, 서버 정책, 대상 22번 포트 검사
- **Permission denied:** 대상 SSH 사용자·키·sshd 권한 검사
- **서비스 제거:** 소유 Agent에서 **unset remote-service support-ssh** 실행 전 포트 예약과 연결 중단 영향을 확인합니다. 단일 서비스 때문에 전체 Managed Host를 삭제하지 마세요.
