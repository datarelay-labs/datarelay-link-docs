# 빠른 시작

<Note>
  먼저 [Server 설치](/ko/getting-started/server-installation)를 완료하세요. 아래 명령은 실행 위치를 Server와 Agent Host로 구분하여 입력합니다.
</Note>

## 1. Server 확인

```bash
sudo drlink
```

```text
system version
show status
system diagnostics
```

Role이 DRLink Server인지 확인합니다.

## 2. Zero-Touch 발급

Server에서:

```text
set enrollment zero-touch
```

**Linux** → Managed Host 이름·설명 → **SSH only** → 실제 SSH 포트(기본 22)를 선택하고 발급된 명령을 대상 Host에서 실행합니다.

Zero-Touch에서 **SSH only**, **RDP only** 또는 **Choose Remote Services**로 선택한 서비스는 등록 시 Service Object·Remote Service·공인 포트 예약까지 자동 구성됩니다. 같은 서비스를 수동으로 다시 생성하지 않습니다. Agent에서 `show remote-services`로 실제 이름을 확인하세요.

**SSH only에서 사용자명을 비우는 것은 접속 예시만 생략하는 것이며 management-only 등록이 아닙니다.** 서비스 없이 등록하려면 `set enrollment bulk`에서 count **1**, SSH 사용자명 빈 값으로 발급합니다. Choose Remote Services는 서비스가 하나 이상 필요합니다. OS 계정·sshd/RDP·외부 방화벽·Access Policy Rule은 별도입니다.

## 3. Agent Host 확인

Agent Host에서:

```text
show status
show agent
```

## 4. 자동 생성된 Remote Service 확인

Agent Host에서:

```text
show remote-services
show remote-service <actual-service-name>
```

## 5. 필요하면 Remote Access 제한

Server에서:

```text
set network-object office-admin type ip value 203.0.113.10
set remote-access office-ssh mode whitelist source office-admin destination <managed-host> service ssh enabled
set remote-access enabled
test remote-access source office-admin destination <managed-host> service ssh
```

## 6. 접속

```bash
ssh -p <public-port> <user>@<public-hostname>
```

DataRelay Link는 OS 계정이나 sshd 설정을 만들지 않습니다.

`<actual-service-name>`과 정책의 `ssh`는 목록의 실제 Remote Service·Service Object 이름으로 바꾸세요. 외부 공개 전 필요한 정책을 검토하고 기존 Object를 덮어쓰지 마세요.
