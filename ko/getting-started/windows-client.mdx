# Windows Agent Host

Windows는 Agent Host 플랫폼입니다. DRLink Server는 Linux 기반입니다.

Server에서 생성한 Enrollment 명령만 사용합니다.

## 등록

Server에서:

```text
set enrollment zero-touch
```

마법사에서 **Windows → RDP only** 또는 **Choose Remote Services**를 선택하고 호스트 이름·설명과 실제 대상 포트를 입력합니다. Zero-Touch에서 **SSH only**, **RDP only** 또는 **Choose Remote Services**로 선택한 서비스는 등록 시 Service Object·Remote Service·공인 포트 예약까지 자동 구성됩니다. 같은 서비스를 수동으로 다시 생성하지 않습니다. Agent에서 `show remote-services`로 실제 이름을 확인하세요.

발급된 Windows 설치/등록 명령을 제품 설치 안내에 따라 실행합니다.

## 확인

```text
show status
show agent
system info
system diagnostics
```

## RDP

RDP는 TCP/3389 Service Object로 표현할 수 있습니다. DataRelay Link는 Windows RDP를 활성화하거나 계정을 만들거나 Windows Firewall/NLA를 약화시키지 않습니다.

Agent lifecycle에서는 pause, resume, restart, product update, engine update, diagnostics, support bundle, uninstall을 사용합니다.

## 등록된 Agent 업데이트

Server를 먼저 업데이트한 다음, 이미 등록된 Windows Agent Host의 관리자 PowerShell에서 실행합니다.

```powershell
drlink system update product
drlink system version
drlink system diagnostics
```

제품 업데이트는 기존 pinned HTTPS 관리 연결에서 Server가 검증한 Bootstrap을 받아 불변 소스 및 SHA256을 확인하고 Agent ID, 기존 서비스와 포트를 보존합니다. Zero-Touch를 다시 실행하지 않습니다. Source HEAD가 UNKNOWN이거나 일치하지 않으면 실제 업데이트 결과를 확인하고 버전·출처 기록을 임의 수정하지 않습니다. Relay Engine 업데이트는 별도입니다 (`drlink system update engine`).

## AI 실행

Connected와 AI Executor Ready는 별개입니다. Windows lifecycle worker는 관리자가 기존 보호된 로컬 실행 프로필을 명시적으로 활성화한 경우에만 AI Job을 수신합니다. Server의 AI Access Rule은 별도 권한 정책이며 로컬 계정 SID, 허용 드라이브 경로 및 명령 실행 승인은 독립된 OS 실행 제한입니다. 설치/업데이트는 제품 소유 코드·실행 파일 트리의 비인가 변경을 차단하며 OS 상위 디렉터리 ACL, 기존 등록 및 실행 프로필은 변경하지 않습니다. Diagnostics에서 안전하지 않은 코드 ACL과 실행 프로필 미설정·오류를 구분합니다. 실제 등록된 Windows Agent에서 허용된 도구 호출을 검증해야 합니다. [MCP 도구](/ko/reference/mcp-tools)를 참조하세요.
