# SSH Remote Service

SSH는 일반적으로 destination TCP/22 Service Object를 사용합니다.

## 신규 호스트는 Zero-Touch로 구성

Server에서 `set enrollment zero-touch`를 실행하고 플랫폼·호스트 이름·설명을 입력합니다. **SSH only**에서 실제 SSH 포트(기본 22)를 지정합니다. 발급된 명령을 대상 호스트에서 실행하면 선택한 서비스는 자동 구성됩니다. `show remote-services`로 실제 이름과 접속 주소를 확인하고, 같은 서비스를 아래 수동 절차로 중복 생성하지 않습니다.

## 기존 Agent에 추가할 때

아래 수동 구성은 이미 등록된 Agent에 **새 서비스**를 추가하는 경우입니다. 먼저 Server의 `show service-objects`와 Agent의 `show remote-services`로 기존 정의를 확인하고 없는 항목만 만드세요.

## 1. Service Object

Server:

```text
set service-object ssh type tcp port 22
```

## 2. Remote Service

소유 Agent Host:

```text
set remote-service ssh-access destination this-host service ssh enabled
show remote-service ssh-access
```

다른 LAN Host의 SSH를 중계하려면 해당 destination을 지정합니다. 현재 Agent Host가 Relay Host가 됩니다.

## 3. 필요하면 Remote Access 제한

Server:

```text
set network-object office-admin type ip value 203.0.113.10
set remote-access office-ssh mode whitelist source office-admin destination <managed-host> service ssh enabled
set remote-access enabled
test remote-access source office-admin destination <managed-host> service ssh
```

## 4. 접속

Agent의 show remote-service가 표시한 endpoint를 사용합니다.

```bash
ssh -p <public-port> <user>@<public-hostname>
```

DataRelay Link는 SSH 계정, SSH key, sshd 설정을 만들지 않습니다.

## 장애 확인 순서

1. test remote-access 결과 확인
2. Agent Host에서 show remote-service ssh-access
3. Agent Host에서 target TCP/22 reachability 확인
4. 외부에서 public endpoint reachability 확인
5. SSH user/key/authentication 확인

Policy ALLOW가 target reachability를 보장하지는 않습니다.

정책의 IP·Managed Host·서비스 이름은 실제 값으로 바꾸세요. 기존 정책 Mode와 다른 허용 Rule도 확인합니다.
