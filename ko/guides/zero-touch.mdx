# Zero-Touch 등록

Server에서:

```text
set enrollment zero-touch
```

## 제한

```text
요청당 최대 발급        10
동시 활성 미사용 ticket 10
기본 TTL                1시간
최대 TTL                24시간
사용 횟수               1회
```

등록 자격 증명은 고유하며 등록 성공 시 원자적으로 소비됩니다. 원본 자격 증명은 공개하지 않으며 Server에는 검증 정보와 상태를 보존합니다.

Zero-Touch는 Agent를 등록합니다. OS 사용자, SSH 설정, cloud firewall, Access Policy Rule을 자동 생성하지 않습니다.

## 명령 구성 항목 (다음 제품 후보 설계)

고객에게 전달하는 명령은 아래 항목으로만 구성합니다. 공인·사설 HTTPS에 동일한 형식을 적용하며, DNS는 필수가 아닙니다. Server 주소와 파일명만 변경됩니다.

| 항목 | Linux/macOS | Windows (관리자 PowerShell) |
|---|---|---|
| 다운로드 | `curl` | `curl.exe` |
| 옵션 | `-kfsS` | `-kfsS` |
| 프로토콜 | `https://` | `https://` |
| Server 주소 | FQDN 또는 IP, 필요 시 설정된 포트 | 동일 |
| Bootstrap 파일명 | `/` + 6자리 파일명 | 동일 |
| 실행 | `\|sudo bash` | `iex(...\|Out-String)` |

```bash
curl -kfsS https://remote.xdr.ooo/A3xK9m|sudo bash
```

```powershell
iex(curl.exe -kfsS https://remote.xdr.ooo/A3xK9m|Out-String)
```

위 예시는 다음 제품 후보의 설계 형식이며 실제 사용 가능한 발급 명령이 아닙니다. 설치 및 등록에 필요한 추가 파일, 설정, 검증과 복구는 Bootstrap에서 처리합니다. 동일 명령으로 설치를 재시도하되 중복 등록하지 않습니다. 6자리 파일명은 등록 자격 증명이 아닙니다. 최초 `-k` 다운로드는 서버 인증을 제공하지 않으며, 후속 연결과 별도의 등록 인증 및 실제 OS 검증은 제품 릴리즈 전 확인해야 합니다. SSH 사용자명은 비워도 됩니다.

## 자동 구성과 추가 구성

Zero-Touch에서 **SSH only**, **RDP only** 또는 **Choose Remote Services**로 선택한 서비스는 등록 시 Service Object·Remote Service·공인 포트 예약까지 자동 구성됩니다. 같은 서비스를 수동으로 다시 생성하지 않습니다. Agent에서 `show remote-services`로 실제 이름을 확인하세요.

**SSH only에서 사용자명을 비우는 것은 접속 예시만 생략하는 것이며 management-only 등록이 아닙니다.** 서비스 없이 등록하려면 `set enrollment bulk`에서 count **1**, SSH 사용자명 빈 값으로 발급합니다. Choose Remote Services는 서비스가 하나 이상 필요합니다. OS 계정·sshd/RDP·외부 방화벽·Access Policy Rule은 별도입니다.

기존 Agent에 새 목적지/포트를 추가할 때만 Server의 Object 정의를 확인·준비하고 소유 Agent에서 `set remote-service <NAME>`을 사용합니다.
