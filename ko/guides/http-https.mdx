# HTTP & HTTPS Remote Service

HTTP/HTTPS는 일반 TCP Service Object로 정의합니다.

Server:

```text
set service-object http type tcp port 80
set service-object https type tcp port 443
```

Agent Host:

```text
set remote-service web-http destination this-host service http enabled
set remote-service web-https destination this-host service https enabled
```

다른 LAN Host를 destination으로 지정하면 현재 Agent Host가 Relay Host가 됩니다.

## 신규 호스트는 Zero-Touch로 구성

Server에서 `set enrollment zero-touch`를 실행하고 플랫폼·호스트 이름·설명을 입력합니다. **Choose Remote Services**에서 서비스 유형과 대상 호스트·포트를 지정합니다. 발급된 명령을 대상 호스트에서 실행하면 선택한 서비스는 자동 구성됩니다. `show remote-services`로 실제 이름과 접속 주소를 확인하고, 같은 서비스를 아래 수동 절차로 중복 생성하지 않습니다.

## 기존 Agent에 추가할 때

아래 수동 구성은 이미 등록된 Agent에 **새 서비스**를 추가하는 경우입니다. 먼저 Server의 `show service-objects`와 Agent의 `show remote-services`로 기존 정의를 확인하고 없는 항목만 만드세요.

## HTTPS

Remote Service는 TCP를 전달합니다. DataRelay Link가 target application의 HTTPS TLS를 종료하거나 certificate를 교체하지 않습니다.

브라우저가 Remote Service endpoint를 통해 HTTPS target에 접속할 경우 certificate name/SAN 검증은 실제 application TLS endpoint 설계와 일치해야 합니다.

Remote Service 사용자를 제한하려면 Server의 Remote Access Policy를 별도로 설정합니다.

## 장애 확인

- policy authorization: test remote-access 결과
- Agent/runtime 상태: show remote-service
- target 연결성: Agent Host에서 실제 target TCP reachability
- HTTPS warning: target certificate/SAN

Authorization ALLOW와 runtime HEALTHY는 서로 다른 판단입니다.
