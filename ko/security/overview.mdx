# 보안 개요

## Enrollment

Zero-Touch ticket은 한 번만 사용할 수 있고 유효 시간이 있습니다. 원본 ticket 값은 나중에 다시 조회할 수 있는 비밀값으로 저장하지 않습니다.

## Agent identity

Managed Host identity는 호스트명, label, 관찰된 NAT/공인 IP만으로 결정하지 않고 등록된 Agent와 machine identity를 기준으로 합니다.

## Access Policy

| 정책 | 지원 모드 | 정책 없음 | Enforcement disabled |
| --- | --- | --- | --- |
| Remote Access | BLACKLIST / WHITELIST | ALLOW | ALLOW ALL |
| Internet Access | WHITELIST 전용 | DENY | DENY ALL |
| AI Access | WHITELIST 전용 | DENY | DENY ALL |

WHITELIST는 매칭 허용 Rule이 없으면 DENY입니다. BLACKLIST는 Remote Access에서만 지원하며 매칭하면 DENY, 미일치면 ALLOW입니다. Rule 순서와 Rule별 action은 없습니다. 정책 초기화는 Mode/Rule을 삭제하고 각 정책의 초기 상태로 돌아갑니다. AI 인증은 정책 상태와 별도로 항상 필요합니다.

## Internet Access

Open proxy가 되지 않도록 목적지·프로토콜·포트를 검증하고, DNS rebinding과 SSRF를 방어하며 private/local/metadata 주소 접근을 차단합니다.

## AI 인증

AI 표시 이름만으로는 인증되지 않습니다. 지원되는 OAuth 또는 명시적인 인증 정보로 AI Identity를 확인해야 합니다. AI Access enforcement가 disabled여도 인증은 필수입니다.

## Secret

설정 내보내기, 지원 번들, 로그, AI에 복사해 붙이는 내용에서는 enrollment ticket, OAuth/bearer secret, private key 같은 민감한 값을 제거해야 합니다.
