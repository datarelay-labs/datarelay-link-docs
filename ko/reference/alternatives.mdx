# DataRelay Link 및 상용 대안 비교

모든 환경에 가장 적합한 단일 연결 도구가 있는 것은 아닙니다. 어떤 선택이 맞는지는 **직접 운영하는 공개 릴레이**, **관리형 인터넷 인그레스**, **사설 오버레이 네트워크**, 또는 **제어된 아웃바운드 게이트웨이** 중 무엇이 필요한지에 따라 달라집니다.

이 페이지는 벤치마크 성능이나 가격이 아니라 **운영 모델과 활용 방식**을 비교합니다. 상용 서비스의 기능과 요금제 제한은 자주 바뀔 수 있으므로 구매 전에는 각 공급사의 최신 문서를 확인하세요.

## 한눈에 비교

| 선택지 | 기본 모델 | 공개 Edge / Control Plane 운영 주체 | 원격 사이트에서 inbound 방화벽 오픈 필요? | 적합한 환경 |
| --- | --- | --- | --- | --- |
| **DataRelay Link** | Self-hosted secure relay + enrollment/lifecycle + Internet Access | 사용자 | Managed Host에는 불필요 | 직접 공개 서버를 운영하고, 예측 가능한 Remote Service endpoint와 명시적인 outbound 정책을 원하는 수 대~수십 대 환경 |
| **수동 Self-hosted reverse proxy** | 직접 관리하는 tunnel/reverse proxy 구성 | 사용자 | 일반적으로 Managed Host에는 불필요 | 저수준 설정의 최대 유연성이 필요하고 설정을 직접 유지할 수 있는 엔지니어 |
| **ngrok** | 관리형 Internet ingress / agent endpoint | ngrok | 일반적으로 불필요 | 개발, webhook, demo, 임시 또는 관리형 공개 endpoint, TCP/SSH 활용 |
| **Cloudflare Tunnel** | Cloudflare Zero Trust/global edge로 outbound connector 연결 | Cloudflare | 불필요 | 공개 Web application 및 조직 관리형 private application access |
| **Tailscale** | WireGuard 기반 private mesh network + 선택적 Serve/Funnel | Tailscale coordination service | 불필요 | 팀/tailnet 내부의 private device-to-device 또는 user-to-service 연결 |

## DataRelay Link가 잘 맞는 경우

다음 요구가 여러 개 동시에 중요하다면 DataRelay Link가 적합합니다.

- 공개 relay server와 IP 주소를 직접 소유하고 운영하고 싶다.
- 원격 시스템이 NAT/방화벽 뒤에 있고 outbound 방식으로 연결되어야 한다.
- 기술지원 인력이 VPN에 먼저 접속하지 않고 SSH/HTTP/HTTPS/custom TCP에 직접 접근해야 한다.
- 하나의 Agent Host에서 여러 local 또는 reachable LAN target을 Remote Service로 연결해야 한다.
- Zero-Touch enrollment, Managed Host identity, persistent Remote Service endpoint, lifecycle control, diagnostics, backup/restore가 필요하다.
- 제한망 시스템이 전체 Internet이 아니라 승인된 HTTP/HTTPS 목적지에만 접근해야 한다.
- 환경 규모가 대규모 fleet이 아니라 수 대에서 수십 대 수준이다.

## 수동 Self-hosted reverse proxy가 더 나은 경우

저수준 프로토콜과 설정에 대한 최대한의 자유도가 필요하고 enrollment, identity, policy, lifecycle, diagnostics, backup, upgrade를 직접 구축하고 유지할 수 있다면 수동 Self-hosted reverse proxy/tunnel이 더 적합할 수 있습니다.

DataRelay Link는 이런 저수준 자유도를 일부 줄이는 대신 소규모 환경에서 더 단순하고 일관된 운영 모델을 제공하는 것을 목표로 합니다.

## ngrok가 더 나은 경우

직접 공개 relay server를 운영하기보다 관리형 public edge를 선호한다면 ngrok가 더 적합할 수 있습니다. 특히 개발용 endpoint, webhook, demo, 관리형 TCP endpoint를 빠르게 구성하는 데 편리합니다.

## Cloudflare Tunnel이 더 나은 경우

조직에서 이미 Cloudflare Zero Trust를 사용하고 있거나 application을 Cloudflare edge 뒤에 배치하려는 경우 Cloudflare Tunnel이 잘 맞습니다. Outbound-only connector를 사용하므로 공개적으로 routable한 origin이 없어도 되고, private networking과 Gateway policy까지 포함하는 더 넓은 관리형 Zero Trust 생태계를 제공합니다.

## Tailscale이 더 나은 경우

주된 목적이 **raw public service port 공개가 아니라 private network membership**이라면 Tailscale이 더 적합합니다. WireGuard 기반 mesh network를 만들고 identity 및 access-control policy를 결합합니다.

## 선택 가이드

| 요구사항 | 먼저 검토할 선택지 |
| --- | --- |
| Self-hosted public relay, 소규모 환경, 직접 SSH/TCP, Internet Access | **DataRelay Link** |
| 저수준 설정 자유도가 가장 중요하고 수동 운영이 가능 | **수동 Self-hosted reverse proxy** |
| 개발/webhook/demo를 위한 빠른 관리형 public endpoint | **ngrok** |
| Cloudflare 중심의 public app 또는 Zero Trust private application access | **Cloudflare Tunnel** |
| Identity 기반 private team/device mesh network | **Tailscale** |
