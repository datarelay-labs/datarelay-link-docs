## 대상과 실행 계정

Managed Host endpoint는 **list_hosts/get_host가 반환한 식별자**를 사용하세요. server_*와 get_server는 Server 자체이며 endpoint 인자를 받지 않습니다. 일반 도구의 endpoint=server:self는 해당 Server-self 기능·profile·권한이 허용할 때만 사용할 수 있습니다.

Server-self discovery와 local executor는 운영자가 별도 활성화합니다. 전체 제어에서는 셸·Git·서비스·패키지 작업이 선택한 OS 계정 권한으로 동작하며 root는 별도 opt-in입니다. **cwd는 시작 위치 검증이지 셸의 파일시스템 샌드박스가 아닙니다.** restricted 프로필은 일반 셸/쓰기 Git과 기능이 다릅니다.

## 인자와 결과

| 도구 | 선택 인자 / 동작 |
| --- | --- |
| server_exec / server_run / server_git | timeout_seconds: 1–86400, 기본 3600; wait_ms: 0–5000, 기본 1000 |
| server_job_poll | stdout_cursor / stderr_cursor: 바이트 offset, 기본 0; wait_ms: 0–5000 |
| server_job_input | data: UTF-8 문자열, 기본 빈 값; eof: boolean, 기본 false |

argv는 문자열 배열이며 server_git의 첫 값은 git입니다. path와 cwd는 절대경로입니다. 실행 결과의 **job_id, state, exit_status, stdout, stderr, execution_user**를 확인하세요. running은 성공 완료가 아닙니다. poll은 각 스트림의 **next_cursor**로 이어 읽고, 정확한 바이트가 필요하면 **data_b64**를 사용합니다. 출력은 스트림당 최대 1 MiB 보존/페이지당 64 KiB이며 cursor eviction을 확인해야 합니다. stdin도 64 KiB 한도이며 **accepted_bytes**로 수락 범위를 확인하세요. 완료 작업은 최대 10분 또는 제한된 기록 정리 때까지만 조회됩니다. 재시작 후 보존을 보장하는 영구 작업 큐가 아닙니다.

poll/input/stop도 현재 command-exec 권한과 동일 identity/job ownership을 다시 확인합니다. 다른 identity의 job_id를 안다고 제어할 수 없습니다. file-read/write/upload/download는 별도 권한과 Rule의 paths, 실제 OS 권한을 충족해야 합니다.
