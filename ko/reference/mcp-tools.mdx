# Native MCP 도구 20개

DataRelay Link가 제공하는 MCP 도구의 이름·필수 인자·권한을 정리했습니다. 클라이언트가 붙이는 namespace는 다를 수 있습니다. 아래 항목은 CLI 명령이 아니라 AI가 호출하는 MCP 도구입니다.

| 도구 | 필수 인자 | DRLink 권한 | 용도 |
| --- | --- | --- | --- |
| **get_server** | 없음 | host-info | Server 자체 조회 |
| **list_hosts** | 없음 | host-info | 접근 가능한 Managed Host 목록 |
| **get_host** | endpoint | host-info | Managed Host 조회 |
| **get_system_info** | endpoint | host-info | 시스템 정보 |
| **list_processes** | endpoint | process-read | 프로세스 조회 |
| **read_file** | endpoint, path | file-read | 허용 파일 읽기 |
| **write_file** | endpoint, path, content | file-write | 허용 파일 쓰기 |
| **delete_file** | endpoint, path | file-write | 일반 파일 삭제 |
| **upload_file** | endpoint, path, content | file-upload | 파일 업로드 |
| **download_file** | endpoint, path | file-download | 파일 다운로드 |
| **exec** | endpoint, command | command-exec | 대상 명령 실행 |
| **server_read_file** | path | file-read | Server 파일 읽기 |
| **server_write_file** | path, content | file-write | Server 파일 쓰기 |
| **server_delete_file** | path | file-write | Server 파일 삭제 |
| **server_run** | cwd, argv | command-exec | 전체 제어 모드 argv 실행 |
| **server_exec** | cwd, command | command-exec | 셸 명령 실행 |
| **server_git** | cwd, argv | command-exec | Git 조회·수정·commit/push |
| **server_job_poll** | job_id | command-exec | 작업 상태·출력 조회 |
| **server_job_input** | job_id | command-exec | 표준 입력·EOF 전달 |
| **server_job_stop** | job_id | command-exec | 본인 작업 중지 |

## 대상과 실행 계정

현장 개선 후보 버전에서 Managed Host endpoint는 **list_hosts가 반환한 정확한 이름 또는 전체 client_id**를 사용합니다. 두 식별자에 동일한 AI Access 정책을 적용하며, 축약 ID 및 모호한 식별자는 차단합니다. Agent 연결 상태와 AI Executor 준비 상태는 별개이며, Windows lifecycle heartbeat만으로는 AI Executor 준비를 보장하지 않습니다. 후보 버전의 Windows 네이티브 Executor는 관리자가 실행 계정 SID에 바인딩된 보호 로컬 프로필과 허용 드라이브 경로를 별도로 설정하고 명령 실행을 명시적으로 허용하기 전까지 비활성화됩니다. 파일 작업은 서버 및 로컬 경로 정책을 모두 충족해야 하며 UNC, 장치 경로, 대체 스트림 및 재분석 지점 탐색은 거부됩니다. Windows 네이티브 검증은 별도로 필요합니다. server_*와 get_server는 Server 자체이며 endpoint 인자를 받지 않습니다. 일반 도구의 endpoint=server:self도 명시적으로 부여한 Server 관리 권한을 따릅니다. 후보 버전의 `system diagnostics mcp`는 자격증명 공개나 권한 변경 없이 실행 중인 Bridge의 허용된 게이트 상태만 표시합니다. Unknown은 실제 런타임 상태를 확인하지 못했다는 의미입니다.

Server 자체의 셸·Git·서비스·패키지 작업은 설정된 OS 계정 권한과 AI Access를 따릅니다. **cwd는 시작 위치 검증이지 셸의 파일시스템 샌드박스가 아닙니다.**

Server 설치 및 제품 업데이트는 기존 명시적 실행 프로필이 없으면 비관리자 전용 실행 계정과 작업 디렉터리를 준비하되 원격 실행을 활성화하지 않습니다. 기존 `set ai-mcp` → Configure local Server execution account에서 OS 실행 계정과 경로를 한 번 승인합니다. UID 0은 별도의 명시적 로컬 승인이 필요합니다. 새로운 AI Access Rule은 생성하지 않으며 기존 프로필을 보존합니다. `system diagnostics mcp`는 실행 환경의 비활성화·미완성·구성 상태를 구분하며 실제 호출은 기존 AI Access Rule을 따릅니다.

## 인자와 결과

| 도구 | 선택 인자 / 동작 |
| --- | --- |
| server_exec / server_run / server_git | timeout_seconds: 1–86400, 기본 3600; wait_ms: 0–5000, 기본 1000 |
| server_job_poll | stdout_cursor / stderr_cursor: 바이트 offset, 기본 0; wait_ms: 0–5000 |
| server_job_input | data: UTF-8 문자열, 기본 빈 값; eof: boolean, 기본 false |

argv는 문자열 배열이며 server_git의 첫 값은 git입니다. path와 cwd는 절대경로입니다. 실행 결과의 **job_id, state, exit_status, stdout, stderr, execution_user**를 확인하세요. running은 성공 완료가 아닙니다. poll은 각 스트림의 **next_cursor**로 이어 읽고, 정확한 바이트가 필요하면 **data_b64**를 사용합니다. 출력은 스트림당 최대 1 MiB 보존/페이지당 64 KiB이며 cursor eviction을 확인해야 합니다. stdin도 64 KiB 한도이며 **accepted_bytes**로 수락 범위를 확인하세요. 완료 작업은 최대 10분 또는 제한된 기록 정리 때까지만 조회됩니다. 재시작 후 보존을 보장하는 영구 작업 큐가 아닙니다.

poll/input/stop도 현재 command-exec 권한과 동일 identity/job ownership을 다시 확인합니다. 다른 identity의 job_id를 안다고 제어할 수 없습니다. file-read/write/upload/download는 별도 권한과 Rule의 paths, 실제 OS 권한을 충족해야 합니다.
