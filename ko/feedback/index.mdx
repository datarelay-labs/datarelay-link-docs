# 피드백

재현 가능한 문제나 실제 운영에서 필요한 개선점을 알려주세요.

## 제출 전에

1. 기존 GitHub Issue를 검색합니다.
2. 실제 설치된 DataRelay Link version과 가능한 경우 Source HEAD를 적습니다.
3. Server 또는 Agent Host 역할과 영향받은 기능을 적습니다.
4. 가장 짧고 안정적인 재현 절차를 제공합니다.
5. 비밀정보와 고객 데이터를 제거합니다.

<Warning>
  비밀번호, 개인키, enrollment ticket, OAuth/bearer token, API key, 고객 데이터를 공개 Issue에 올리지 마십시오.
</Warning>

## 유용한 버그 정보

- DataRelay Link version / release channel / Source HEAD
- Server 또는 Agent Host platform/role
- 관련 Managed Host public name
- 관련 Remote Service, Object/Group, Access Policy 이름
- 필요한 경우 deployment mode / NAT / firewall context
- 기대 동작과 실제 동작
- 정확한 재현 절차
- 필요한 범위의 redacted show/status/test/system diagnostics 출력
- reconnect, reboot, update, restore 등 lifecycle 이벤트 연관 여부

## 기능 개선 영역

- Managed Host enrollment/lifecycle
- Network / Service / Permission Object와 Group
- Remote Service / Remote Access
- Internet Access
- AI Identity / AI Access / MCP
- ConfigurationBundle / AI-assisted configuration
- CLI / operator UX
- update / backup / restore / diagnostics / support bundle
- Linux / macOS / Windows Agent Host
- 문서

DataRelay Link의 목표 규모는 몇 대에서 몇십 대의 Managed Host이며 대규모 fleet orchestration이나 전체 SASE/SWG 제품이 아닙니다.
