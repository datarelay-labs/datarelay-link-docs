# 배포 및 네트워크 설정

DataRelay Link Server는 Direct와 Enterprise single-443 두 배포 모드를 지원합니다.

<Note>처음 설치한다면 [작업별 최초 설정 경로](/ko/getting-started/choose-workflow)를 확인하세요.</Note>

## Direct

일반적인 public listener:

```text
TCP/443        Relay control
TCP/6099       management/enrollment HTTPS
TCP/6000-6098 Remote Service endpoint pool
```

## Enterprise single-443

Management/Enrollment HTTPS와 Relay control이 public TCP/443을 공유하고 내부 backend listener는 loopback-only로 유지됩니다.

Remote Service endpoint는 설정된 endpoint pool에서 별도로 할당됩니다.

배포 모드를 바꾸더라도 v2.4 control-plane DB, Managed Host/Agent identity, Remote Service, endpoint 예약, 정책, 신뢰 정보는 그대로 유지되어야 합니다.

설치 프로그램은 cloud security group, 외부 firewall/NAT, DNS provider record를 자동 변경하지 않습니다.

## MCP를 사용하는 경우

공개 원격 MCP는 **single443** 전용입니다. Direct의 TCP/443 Relay 제어는 HTTPS MCP가 아닙니다. [Claude / ChatGPT 연결 가이드](/ko/guides/mcp-clients)를 따르세요. 배포 모드를 바꾸면 연결이 끊길 수 있으므로 동일한 불변 소스의 installer와 검증한 백업으로 계획된 전환을 수행합니다.

## 방화벽, NAT 및 포트

실제로 설정한 endpoint pool과 필요한 포트만 노출합니다. Fixed TCP는 별도로 설정한 endpoint pool을 사용하며 Service Object의 destination port와 public endpoint port는 다릅니다. single443의 내부 allocator/Relay Engine backend는 loopback에만 유지합니다. Managed Host는 Server에 아웃바운드로 연결하므로 Agent 동작만을 위해 공인 IP나 inbound NAT가 필요하지 않습니다. 제품은 UFW/firewalld, 외부 라우터 또는 고객 방화벽의 NAT/DNAT 규칙을 자동 변경하지 않습니다.

## DNS & Public Hostname

DataRelay Link는 다음 이름을 구분합니다.

| 이름 | 용도 |
| --- | --- |
| Product public identity | 설치 시 선택하는 Server control/management identity |
| Remote Service alias | Remote Service endpoint용 optional friendly hostname |
| Bootstrap hostname | Zero-Touch bootstrap entry용 optional hostname |

설치에서 domain을 product public identity로 선택했다면 생성되는 Zero-Touch 및 product-facing URL에 일관되게 사용되어야 합니다.

Remote Service alias를 바꿔도 Agent identity, policy selector, Server trust identity가 자동 변경되면 안 됩니다.

DNS provider record는 DataRelay Link가 자동 생성하지 않습니다.
