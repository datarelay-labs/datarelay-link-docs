# CLI 명령어 전체 참조

현재 제품의 Server·Agent 공개 CLI를 정리했습니다. MCP 도구는 [MCP 도구 참조](/ko/reference/mcp-tools)에서 확인하세요.

Linux 셸에서 **sudo drlink**로 REPL에 들어가면 아래 명령을 그대로 입력합니다. 일반 셸에서 실행할 때는 각 줄 앞에 **sudo drlink**를 붙이세요. 꺾쇠괄호 값은 실제 값으로 바꿔야 합니다. 이름까지만 입력한 **set**은 생성/수정 마법사를 열고, 필드를 모두 준 명령은 필요한 영향도 확인 후 직접 적용합니다.

Server는 Managed Host/등록, Object/Group, AI MCP Setup/Identity, 정책, 감사·백업·복구와 Server ConfigurationBundle을 관리합니다. Agent는 자신의 Remote Service, Agent 수명주기, 진단 및 Agent ConfigurationBundle을 관리합니다. 잘못된 역할의 명령은 적절한 실행 위치를 안내합니다. [ConfigurationBundle](/ko/drlink/configuration-bundle)을 참고하세요.

## Server 조회

`show managed-host-groups`는 그룹과 멤버 수를 표시합니다. `show managed-host-group <GROUP>`은 그룹 정보와 실제 멤버의 전체 HOST ID, NAME, HOSTNAME을 표시하고 빈 그룹을 명시합니다. 멤버가 없는 그룹도 Tab으로 이름을 자동완성할 수 있습니다. Managed Host 선택 목록은 호스트별 한 행에 전체 Host ID를 표시합니다.

## Server 생성과 수정

~~~text
set enrollment zero-touch
set enrollment manual
set enrollment bulk

set server public-hostname <FQDN>
set server bootstrap-hostname <FQDN>
set server installer-url <URL>
set server windows-installer-url <URL>

set managed-host-group <GROUP>
set managed-host <HOST> group <GROUP>

set network-object <OBJECT>
set network-group <GROUP>

set service-object <SERVICE>
set service-group <GROUP>

set remote-access <RULE>
set remote-access enabled
set remote-access disabled

set internet-access <RULE>
set internet-access enabled
set internet-access disabled

set ai-mcp
set ai-identity <IDENTITY>

set permission-object <PERMISSION>
set permission-group <GROUP>

set ai-access <RULE>
set ai-access enabled
set ai-access disabled

set server mcp hostname <FQDN>
set server mcp mode <auto-acme|user-certificate>
set server mcp contact-email <EMAIL>
set server mcp acme-environment <production|staging>
set server mcp acme-directory <URL>
~~~

~~~text
set network-object github type fqdn value github.com
set network-object office-admin type ip value 203.0.113.10

set network-group approved-admins members office-admin,vpn-admin

set service-object ssh type tcp port 22
set service-object dns-udp type udp port 53
set service-object legacy-db type fixed-tcp port 1521

set service-group web-services members http,https

set permission-object read-only permissions host-info,process-read,file-read
set permission-group observers members read-only

set ai-access allow-read source automation-ai destination ubuntu-prod permission read-only paths '/var/lib/vendor/**' enabled
~~~

일괄 등록 CSV 헤더는 label,ssh_user,note입니다. 미사용 코드 최대 10개, 기본 유효기간 1시간/최대 24시간이며 SSH 사용자명은 비워도 됩니다. 다음 후보의 [Zero-Touch 명령 구성 항목](/ko/guides/zero-touch)은 OS 실행 형식, Server HTTPS 주소, 8자리 Bootstrap 파일명입니다. 공인·사설 HTTPS 형식은 동일하며 최초 유효 Agent가 자동 등록되며 추가 관리자 승인은 필요 없습니다.

## 접근 정책과 파일 경로 범위

~~~text
set remote-access block-partner mode blacklist source partner-office destination ubuntu-prod service ssh enabled
~~~

~~~text
set internet-access github-https mode whitelist source ubuntu-prod destination github service https enabled
~~~

~~~text
set ai-access claude-prod source claude destination production-servers permission read-only paths '/var/log/myapp/**' enabled
set ai-access allow-read source automation-ai destination ubuntu-prod permission read-only paths '/var/lib/vendor/**,/opt/app/**' enabled
~~~

~~~text
set remote-access enabled
set remote-access disabled
set internet-access enabled
set internet-access disabled
set ai-access enabled
set ai-access disabled
~~~

파일 권한에는 절대 경로 scopes가 필요합니다. 예: `/**`, `/home/**`, `/home/**,/opt/**`. 수정 시 생략하면 기존 경로가 유지됩니다. command-exec는 OS 계정 권한으로 실행되며 경로 제한 샌드박스가 아닙니다. 최초 OAuth 연결을 포함해 인증만으로는 권한이 부여되지 않습니다. 별도로 승인한 Rule이 없으면 DENY입니다. 기존 Rule 전체를 확인하세요.

## Server 리소스 삭제

등록 기록 삭제·취소에 사용하는 ID 및 한 번의 확인 절차는 [Managed Host 등록](/ko/guides/enrollment)을 참조하세요.

~~~text
unset managed-host <HOST>
unset managed-host <HOST> group <GROUP>
unset managed-host-group <GROUP>
unset enrollment <ENROLLMENT>

unset server public-hostname
unset server bootstrap-hostname
unset server installer-url
unset server windows-installer-url

unset network-object <OBJECT>
unset network-group <GROUP>

unset service-object <SERVICE>
unset service-group <GROUP>

unset remote-access <RULE>
unset remote-access policy

unset internet-access <RULE>
unset internet-access policy

unset ai-identity <IDENTITY>

unset permission-object <PERMISSION>
unset permission-group <GROUP>

unset ai-access <RULE>
unset ai-access policy

unset server mcp
unset server mcp purge
~~~

삭제 전에 참조를 확인하세요. 그룹 멤버십 제거는 메타데이터 변경이고, bare unset managed-host는 신뢰·엔드포인트 예약을 폐기합니다. 리소스 삭제와 정책 초기화에는 y/N 확인이 적용될 수 있습니다. unset server mcp는 공개 경로를 제거하되 인증서 자료를 보존하고, purge는 대화형 확인 후 보존한 비밀 자료까지 제거합니다.

## 정책 테스트

~~~text
test remote-access source <SOURCE> destination <DESTINATION> service <SERVICE>
test internet-access source <SOURCE> destination <DESTINATION> service <SERVICE>
test ai-access source <AI_IDENTITY> destination <DESTINATION> permission <PERMISSION> [path <PATH>]
~~~

파일 테스트에는 path를 지정하세요. Group은 원자 조합으로 확장되며 전체 ALLOW는 모든 조합이 허용될 때만 표시됩니다. 정책 테스트는 실제 통신이나 MCP 호출 성공을 대신하지 않습니다.

~~~text
system status
system version
system diagnostics

system revisions

system diff <REVISION_A> <REVISION_B>
system rollback <REVISION>

system backup
system backup validate <FILE>

test configuration <FILE|->
system export configuration <FILE>
system diff configuration <FILE|->
system apply configuration <FILE|->

system certificate issue
system certificate import <CERT> <KEY> [CHAIN]

system certificate preflight

set ai-identity <IDENTITY> rotate
set ai-identity <IDENTITY> revoke
set ai-identity <IDENTITY> authentication static-bearer
set ai-identity <IDENTITY> authentication oauth

system backup validate는 읽기 전용이며 restore는 검증·확인 후 현재 상태를 교체합니다. OAuth 페이지의 서버·클라이언트와 새 pending ID를 확인한 뒤 해당 서버에서 승인하세요. 인증서 issue/import/renew는 프런트엔드를 재시작할 수 있으며 TLS 조회는 system certificate status입니다. 제품과 엔진 업데이트는 별도 명령입니다.

~~~

~~~text
set remote-service ssh-access destination this-host service ssh enabled
~~~

~~~text
set remote-service internal-db-postgres destination internal-db service postgres enabled
~~~

Remote Service는 소유 Agent에서 만들고 TCP 또는 Fixed TCP Service Object 1개를 선택합니다. 공개 엔드포인트는 Server가 할당합니다. UDP·Service Group·CIDR/다중 대상·중복 destination+service는 거부됩니다. 런타임 검증 문제는 diagnostics → synchronize → show remote-service 순서로 확인하세요. autostart disable은 다음 부팅에 적용되고 resume은 시작·자동 시작을 복원합니다.

현재 역할의 새 export를 기준으로 작성하세요. apiVersion/kind 필드는 없습니다. 생략한 리소스는 유지하고 state: absent는 명시적으로 삭제합니다. 오래된 sourceRevision은 apply에서 거부됩니다. 원자성은 Server/Agent 각 컨텍스트 내부에 한정됩니다. revision 조건이 맞으면 동일 내용 재적용은 NO CHANGE입니다.

## 정책별 기본 동작

| 정책 | 지원 모드 | 정책 없음/미일치 | Enforcement disabled |
| --- | --- | --- | --- |
| Remote Access | BLACKLIST / WHITELIST | 초기 ALLOW; WHITELIST 미일치 DENY | ALLOW ALL |
| Internet Access | WHITELIST | DENY | DENY ALL |
| AI Access | WHITELIST | DENY | DENY ALL |

Rule 순서나 Rule별 allow/deny 필드는 없습니다. 기존 모드와 충돌하는 mode 변경은 거부됩니다. 첫 Rule에는 mode가 필요합니다.

## 등록 예제의 자동 구성

SSH/RDP/Choose Remote Services로 발급하면 선택한 서비스는 자동 구성됩니다. 기본 실습은 `show remote-services`로 실제 이름을 확인하고 중복 생성하지 않습니다. 단건 SSH only의 빈 사용자명은 SSH 게시를 유지하지만 bulk의 빈 ssh_user는 management-only입니다. 위 명령 목록은 문법 참조이므로 Group 구성원·AI Identity·Managed Host·Service Object는 실행 전에 실제로 존재해야 합니다.
