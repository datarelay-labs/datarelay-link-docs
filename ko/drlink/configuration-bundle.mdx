# ConfigurationBundle

독립적인 리소스 하나만 바꿀 때는 one-shot CLI를 사용합니다. 여러 리소스를 함께 검증하고 모두 성공해야 적용되도록 하려면 ConfigurationBundle을 사용합니다.

## Server 예

~~~yaml
configurationBundle:
  context: server

  networkObjects:
    - name: github
      type: fqdn
      value: github.com

  serviceObjects:
    - name: https
      type: tcp
      port: 443

  internetAccess:
    mode: whitelist
    enforcement: enabled
    rules:
      - name: github-https
        source: ubuntu-prod
        destination: github
        service: https
        enabled: true
~~~

Agent용 bundle은 `context: agent`와 `remoteServices` 섹션을 사용합니다.

~~~text
test configuration <FILE|->
system diff configuration <FILE|->
system apply configuration <FILE|->
system export configuration <FILE>
~~~

stdin interactive paste 종료 표시는 한 줄의 :end 입니다.

## 의미

~~~text
resource 생략    → unchanged
field 생략       → unchanged
state: absent    → 명시적 삭제/reset
동일한 desired   → NO CHANGE
~~~

Server bundle과 Agent bundle은 각각 원자적으로 적용됩니다. 다만 Server와 여러 Agent를 하나의 분산 트랜잭션으로 묶지는 않습니다. 내보내기나 AI에 복사해 붙이는 내용에는 enrollment ticket, OAuth/bearer secret, private key 같은 민감한 값이 포함되어서는 안 됩니다.
