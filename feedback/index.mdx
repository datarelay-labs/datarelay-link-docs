# Feedback

Help improve DataRelay Link by reporting reproducible problems and real workflows that would benefit from improvement.

<CardGroup cols={2}>
  <Card title="Report a Bug" icon="bug" href="https://github.com/datarelay-labs/datarelay-link/issues/new?title=%5BBug%5D%20">
    Report a reproducible problem with version, environment, steps, expected behavior, actual behavior, and redacted diagnostics.
  </Card>

  <Card title="Request a Feature" icon="lightbulb" href="https://github.com/datarelay-labs/datarelay-link/issues/new?title=%5BFeature%5D%20">
    Describe the problem or workflow first, then the behavior you want.
  </Card>
</CardGroup>

## Before you submit

1. Search existing GitHub issues.
2. Report the installed DataRelay Link version and Source HEAD when available.
3. Include the Server or Agent Host role and affected feature.
4. Provide the smallest reliable reproduction sequence.
5. Remove secrets and customer data.

<Warning>
  Never post passwords, private keys, enrollment tickets, OAuth/bearer tokens, API keys, or customer data in a public issue.
</Warning>

## Useful bug-report fields

- DataRelay Link version / release channel / Source HEAD
- Server or Agent Host platform and role
- affected Managed Host public name
- affected Remote Service, Object/Group, or Access Policy name
- deployment mode / NAT / firewall context when relevant
- expected and actual behavior
- exact reproduction steps
- relevant redacted show/status/test/system diagnostics output
- whether reconnect, reboot, update, restore, or another lifecycle event is involved

## Feature-request areas

- Managed Host enrollment and lifecycle
- Network / Service / Permission Objects and Groups
- Remote Services and Remote Access
- Internet Access
- AI Identity, AI Access, and MCP
- ConfigurationBundle and AI-assisted configuration
- CLI and operator UX
- update, backup/restore, diagnostics, and support bundle
- Linux, macOS, and Windows Agent Host compatibility
- documentation

DataRelay Link intentionally targets small environments — a few systems to a few dozen Managed Hosts — rather than large-fleet orchestration or full SASE/SWG scope.
