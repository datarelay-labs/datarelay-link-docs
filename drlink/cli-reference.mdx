# CLI Reference

This reference lists the public Server and Agent commands. See the [MCP tool reference](/reference/mcp-tools) for AI tool calls.

Enter **sudo drlink** for the role-aware REPL. Inside it, omit the sudo drlink prefix. From a Linux shell, prefix each command with **sudo drlink**. Angle-bracket values are placeholders; replace them before running. Bare named **set** opens Guided Create/Edit; complete forms apply directly after any required impact confirmation.

The Server owns Managed Hosts/enrollment, Objects/Groups, AI MCP Setup/Identity, policies, audit/backup/restore and Server ConfigurationBundle. The Agent owns its Remote Services, lifecycle, diagnostics and Agent ConfigurationBundle. Wrong-role operations should identify the correct context. See [ConfigurationBundle](/drlink/configuration-bundle).

## Server: inspect

`show managed-host-groups` lists groups and member counts. `show managed-host-group <GROUP>` lists the group metadata and its actual members, including full HOST ID, NAME, and HOSTNAME; an empty group is explicitly identified. Tab completes current group names even when the group has no members. Managed Host selection displays one row per host, with the full Host ID.

`show managed-services` lists all Server-managed Remote Service mappings, sorted by public port, with Managed Host, service name, target address/port and status. Disabled and pending mappings are included; released mappings are excluded. This is a read-only Server command.

Bulk enrollment accepts count/CSV, header label,ssh_user,note; up to 10 unused codes, 1 hour default TTL and 24 hour maximum. A blank SSH user is valid. For the next candidate, the [Zero-Touch command fields](/guides/zero-touch) define one OS-native invocation, Server HTTPS authority and eight-character Bootstrap filename. Public/private HTTPS share the same form; registration is automatic upon first valid claim; no operator approval is needed.

## Access policies and path scopes

~~~text
set remote-access block-partner mode blacklist source partner-office destination ubuntu-prod service ssh enabled
~~~

~~~text
set internet-access github-https mode whitelist source ubuntu-prod destination github service https enabled
~~~

~~~text
set ai-access claude-prod source claude destination production-servers permission read-only paths '/var/log/myapp/**' enabled
set ai-access allow-read source automation-ai destination ubuntu-prod permission read-only paths '/var/lib/vendor/**,/opt/app/**' enabled
~~~

~~~text
set remote-access enabled
set remote-access disabled
set internet-access enabled
set internet-access disabled
set ai-access enabled
set ai-access disabled
~~~

File permissions require absolute path scopes, e.g. `/**`, `/home/**`, `/home/**,/opt/**`. Omitted paths on edit preserve scopes. Command execution runs with OS account authority, not a path sandbox. OAuth authentication, including the first connection, grants no access by itself. Without an explicitly reviewed matching Rule, access is DENY. Inspect all existing rules.

~~~text
unset network-object <OBJECT>

unset service-object <SERVICE>

unset remote-access <RULE>

unset internet-access <RULE>
unset internet-access policy

unset ai-identity <IDENTITY>

unset ai-access <RULE>
unset ai-access policy

unset server mcp

~~~

Inspect references before deletion. Group membership removal is metadata; bare unset managed-host retires trust and endpoint reservations. Resource deletion and policy reset may require y/N confirmation. unset server mcp removes the public route but retains certificate material; purge additionally removes retained secrets after interactive confirmation.

## Policy tests


Use path for file tests. Groups expand into atomic combinations; aggregate ALLOW requires every member to allow. Policy simulation does not prove real traffic or tool execution.

~~~text

~~~

~~~text
set remote-service internal-db-postgres destination internal-db service postgres enabled
~~~

Remote Services belong to the owning Agent, use exactly one TCP or Fixed TCP Service Object, and receive a Server-allocated endpoint. UDP, Service Groups, CIDR/multiple targets and duplicate destination+service are rejected. Use diagnostics → synchronize → show remote-service when runtime verification is unavailable. Autostart disable affects next boot; resume starts and enables the Agent.

## Policy defaults

| Plane | Modes | No policy / unmatched | Enforcement disabled |
| --- | --- | --- | --- |
| Remote Access | BLACKLIST / WHITELIST | Initial ALLOW; WHITELIST unmatched DENY | ALLOW ALL |
| Internet Access | WHITELIST | DENY | DENY ALL |
| AI Access | WHITELIST | DENY | DENY ALL |

Rules have no ordering or per-rule allow/deny field. An existing conflicting mode is rejected. Specify mode on the first Rule.

## Enrollment example behavior

SSH/RDP/Choose Remote Services enrollment automatically configures selected services. Inspect actual names using `show remote-services`; do not recreate them in a basic onboarding workflow. Blank username in SSH only retains SSH publication; blank ssh_user in bulk means management-only. The inventory above is syntax reference: Group members, AI Identities, Managed Hosts and Service Objects must exist before a referencing command runs.
