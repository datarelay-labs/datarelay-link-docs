# CLI Reference

Checked on **2026-10-28** against the installed Server **help commands** and product CLI Reference at **0feab808aaaa51102d8a7988d09433da916bfcec**. These are v2.4 development commands. Native MCP extensions are versioned separately in the [MCP tools reference](/reference/mcp-tools).

Enter **sudo drlink** for the role-aware REPL. Inside it, omit the sudo drlink prefix. From a Linux shell, prefix each command with **sudo drlink**. Angle-bracket values are placeholders; replace them before running. Bare named **set** opens Guided Create/Edit; complete forms apply directly after any required impact confirmation.

Bulk enrollment accepts count/CSV, header label,ssh_user,note; up to 10 unused codes, 1 hour default TTL and 24 hour maximum. A blank SSH user is valid. Zero-Touch generates a compact one-time launcher using a trusted public hostname or verified numeric-IP/private-CA path; DNS is optional. An unmet prerequisite fails before ticket issuance.

## Access policies and path scopes

~~~text
set remote-access block-partner mode blacklist source partner-office destination ubuntu-prod service ssh enabled
~~~

~~~text
set internet-access github-https mode whitelist source ubuntu-prod destination github service https enabled
~~~

~~~text
set ai-access claude-prod mode whitelist source claude destination production-servers permission read-only enabled
set ai-access allow-read mode whitelist source automation-ai destination ubuntu-prod permission read-only paths '/var/lib/vendor/**',/opt/app/** enabled
~~~

~~~text
set remote-access enabled
set remote-access disabled
set internet-access enabled
set internet-access disabled
set ai-access enabled
set ai-access disabled
~~~

File permissions need rule-bound paths. Omitted paths on edit preserve scopes; paths none clears them. Command execution has the OS account's authority and is stronger than scoped file access. Review the initial OAuth owner's generated mcp-owner-full-access rule: the first approved owner can receive all seven Managed Host capabilities; use a separately scoped identity for read-only users.

## Policy tests

~~~text

test internet-access source <SOURCE> destination <DESTINATION> service <SERVICE>

Use path for file tests. Groups expand into atomic combinations; aggregate ALLOW requires every member to allow. Policy simulation does not prove real traffic or tool execution.

~~~

Remote Services belong to the owning Agent, use exactly one TCP or Fixed TCP Service Object, and receive a Server-allocated endpoint. UDP, Service Groups, CIDR/multiple targets and duplicate destination+service are rejected. Use diagnostics → synchronize → show remote-service when runtime verification is unavailable. Autostart disable affects next boot; resume starts and enables the Agent.

## Policy defaults

| Plane | Modes | No policy / unmatched | Enforcement disabled |
| --- | --- | --- | --- |
| Remote Access | BLACKLIST / WHITELIST | Initial ALLOW; WHITELIST unmatched DENY | ALLOW ALL |
| Internet Access | WHITELIST | DENY | DENY ALL |
| AI Access | WHITELIST | DENY | DENY ALL |

Rules have no ordering or per-rule allow/deny field. An existing conflicting mode is rejected. Specify mode on the first Rule.
