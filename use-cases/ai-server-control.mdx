# Control Server files, Git and jobs from Claude or ChatGPT

**Outcome:** create/read/delete a file, commit locally, exchange stdin/EOF, read output and stop a disposable job. First complete [MCP setup](/guides/mcp-clients). This targets **server:self** under Native MCP full-control, separately from Agent operations.

## Step 1 — operator prepares account and workspace

Assume an existing nonroot **drlink-operator** account owns **/srv/drlink-mcp-lab**. Replace these with actual operator-approved values. Root is unnecessary. **command-exec grants the account's OS authority; cwd is not a filesystem sandbox.**

Keep an already working installation. First-time setup uses the reviewed candidate operator helper. This Server-shell command is **read-only**; point source/HEAD at the actual verified candidate:

~~~bash
python3 tools/operator-native-mcp-full-control.py --check   --source /path/to/verified-source   --head e4f66183fae6bd13a1611e809182838612b4fdc1   --exec-user drlink-operator --allowed-root /srv/drlink-mcp-lab
~~~

After reviewing the plan/account/backup, the operator uses the helper's `--apply` on an authorized Server console. It restarts only the MCP bridge and records a rollback receipt. This is a **development-candidate MCP rollout helper**, not a product release installer. Selecting root additionally needs `--allow-root`. Review the [pinned helper source](https://github.com/datarelay-labs/datarelay-link/blob/e4f66183fae6bd13a1611e809182838612b4fdc1/tools/operator-native-mcp-full-control.py).

## Step 2 — verify the dedicated identity and rule

Assume **mcp-lab** is already OAuth-connected; substitute your actual dedicated identity. **Server REPL:**

~~~text
set permission-object mcp-lab-ops permissions host-info,process-read,file-read,file-write,command-exec
set ai-access mcp-lab-server mode whitelist source mcp-lab destination server:self permission mcp-lab-ops paths '/srv/drlink-mcp-lab/**' enabled
set ai-access enabled
test ai-access source mcp-lab destination server:self permission command-exec path /srv/drlink-mcp-lab
test ai-access source mcp-lab destination server:self permission file-read path /srv/drlink-mcp-lab/note.txt
test ai-access source mcp-lab destination server:self permission file-read path /etc/shadow
show ai-access
~~~

Expect first two policy tests ALLOW, final DENY unless another Rule broadens access. File existence is separate. Upload/download need separately reviewed file-upload/file-download grants.

## Step 3 — file round trip

JSON below describes **MCP tool calls**, not shell commands. Ask either client to use these tools. Pick a unique file if note.txt already exists.

~~~text
Use DRLink MCP get_server to confirm the target first.
Check that /srv/drlink-mcp-lab/note.txt does not exist, then create it
with DRLink MCP tutorial and read it back exactly. Change no other files.
~~~

~~~json
{"tool":"server_write_file","arguments":{"path":"/srv/drlink-mcp-lab/note.txt","content":"DRLink MCP tutorial"}}
{"tool":"server_read_file","arguments":{"path":"/srv/drlink-mcp-lab/note.txt"}}
~~~

Decode base64 where indicated by the response schema and compare the original content. Do not report a failed call as a successful file operation.

## Step 4 — disposable local Git

Use an operator-owned workspace that was empty and is **not an existing repository**. Initialize only there; add only the new note. Do not edit global Git configuration.

~~~json
{"tool":"server_git","arguments":{"cwd":"/srv/drlink-mcp-lab","argv":["git","init"]}}
{"tool":"server_git","arguments":{"cwd":"/srv/drlink-mcp-lab","argv":["git","add","note.txt"]}}
{"tool":"server_git","arguments":{"cwd":"/srv/drlink-mcp-lab","argv":["git","-c","user.name=DRLink Lab","-c","user.email=lab@example.net","commit","-m","Add MCP tutorial note"]}}
{"tool":"server_git","arguments":{"cwd":"/srv/drlink-mcp-lab","argv":["git","log","-1","--oneline"]}}
~~~

Require completed state, exit_status=0 and the resulting commit. Remote push additionally needs an approved remote, network access, that OS account's Git credentials and user authorization. MCP OAuth is not GitHub authentication. Earlier verified push used a disposable local bare remote, not GitHub.

## Step 5 — asynchronous stdin, EOF and output cursors

~~~json
{"tool":"server_run","arguments":{"cwd":"/srv/drlink-mcp-lab","argv":["python3","-u","-c","import sys; print('READY', flush=True); line=sys.stdin.readline(); print('ECHO:'+line.strip(), flush=True)"],"timeout_seconds":60,"wait_ms":1000}}
~~~

Inspect **running**, READY and the **job_id**; send input within 60 seconds. Substitute the actual job ID and stdout.next_cursor (6 after READY in this example). Use the actual Python path if needed.

~~~json
{"tool":"server_job_input","arguments":{"job_id":"<returned-job-id>","data":"DRLink documentation sample\n","eof":true}}
{"tool":"server_job_poll","arguments":{"job_id":"<returned-job-id>","stdout_cursor":6,"stderr_cursor":0,"wait_ms":1000}}
~~~

Expect accepted_bytes=28, input_closed=true, ECHO:DRLink documentation sample and final exit_status=0. If still running, continue with new cursors. If timed out, preserve the failure and create a fresh disposable job before retrying.

## Step 6 — stop only your own job and clean up

~~~json
{"tool":"server_exec","arguments":{"cwd":"/srv/drlink-mcp-lab","command":"sleep 30","timeout_seconds":45,"wait_ms":0}}
{"tool":"server_job_stop","arguments":{"job_id":"<sleep-job-id>"}}
{"tool":"server_delete_file","arguments":{"path":"/srv/drlink-mcp-lab/note.txt"}}
~~~

A stopped job can report completed with a negative signal exit status, distinct from normal exit 0. Stop **only the returned tutorial job**. Let the owning operator review/remove the disposable .git directory; never remove an unrelated repository.

Review `show ai-access-log identity mcp-lab` in Server REPL. Retire the Rule with reviewed `unset ai-access mcp-lab-server` when no longer needed. Do not reset shared AI Access or certificates.
