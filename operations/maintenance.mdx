# Operations Overview

Start with read-only state collection before changing configuration.

## Server

```text
show status
system version
system diagnostics
system audit
system revisions
show managed-hosts
```

## Agent Host

```text
show status
show agent
show remote-services
system info
system diagnostics
```

## Configuration changes

For a single resource, use direct CLI. For dependent multi-resource changes, use ConfigurationBundle:

```text
test configuration <FILE|->
system diff configuration <FILE|->
system apply configuration <FILE|->
```

For recovery, use revisions and the product backup/restore process instead of manually editing runtime state.

A policy ALLOW and real service connectivity are separate. Use policy test commands and Agent/Remote Service state respectively. Escalate with a sanitized support bundle, never raw enrollment tickets, bearer/OAuth secrets, private keys or secret-bearing databases. See [backup/restore](/operations/backup-restore) for the backup procedure.
