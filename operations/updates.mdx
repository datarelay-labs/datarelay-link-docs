# Updates

Inspect the installed product version, channel, Relay Engine version and role with `sudo drlink system version` on the Server or Agent shell. Distribution files and changes are on the [official releases page](https://github.com/datarelay-labs/datarelay-link/releases). Before a Server change, make a [backup](/operations/backup-restore) and verify real connectivity afterward.


The DataRelay Link product version and bundled Relay Engine version are separate.

## Server

```text
system update product
system update engine
system update check-engine
```

## Agent Host

```text
system update product
system update engine
```

Use the built-in product update command. On Windows, run `drlink system update product` in an elevated PowerShell. On the field-convergence candidate, the installed Agent downloads the enrolled Server-qualified manifest and SHA256SUMS over pinned HTTPS, validates the release channel and immutable source, checks the bootstrap SHA256 before invoking upgrade mode, and preserves enrollment. `drlink system update product -Check` verifies metadata without applying software. An explicitly paused Agent remains paused. A failed software refresh restores prior management files and provenance from a protected backup; if rollback fails, retain the reported backup and recover before retrying. Native Windows qualification is required before release. Review the proposed version and restart impact, preserve a Server backup, and verify services after completion.

A normal upgrade must preserve Managed Host/Agent identity, enrollment trust, Remote Service identity, endpoint reservations, control-plane state, policies, and release provenance.

The Server state is stored in SQLite at `/var/lib/drlink/drlink.db`; schema changes use ordered migrations with integrity validation.
